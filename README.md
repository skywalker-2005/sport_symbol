# Символ Спорта

Магазин спортивных наград: React/Vite, Node.js API для Vercel и Layero, PostgreSQL.
API проверяет права пользователя, хранит корзины и заказы, а для оплаты
создаёт платежи ЮKassa на сервере. Сумма и состав заказа рассчитываются по
ценам из базы, а не из запроса браузера.

## Разработка

Нужен Node.js 22 или новее. Для локального запуска API нужна PostgreSQL.
Скопируйте `.env.example` в `.env.local`, заполните переменные окружения,
авторизуйте и привяжите локальную папку к Vercel:

```bash
npm install
npx vercel login
npx vercel link
npx vercel dev
```

Для локальной работы используйте тестовую базу и тестовый магазин ЮKassa.
Обычный `npm run dev` запускает только Vite; API-функции в этом режиме не
работают. Production-сборку фронтенда можно проверить отдельно:

```bash
npm run build
npm run preview
```

## Развёртывание на Vercel

1. Создайте PostgreSQL-базу (например, Neon) с TLS и сохраните строку
   подключения `DATABASE_URL`.
2. Импортируйте репозиторий в Vercel. Укажите **Root Directory**
   `sport_symbol` (папка с `package.json`), команду сборки `npm run build` и
   выходную папку `dist`. `vercel.json` уже содержит эти настройки.
3. В Vercel Project → Settings → Environment Variables добавьте:
   - `DATABASE_URL` — строка PostgreSQL с SSL.
   - `JWT_SECRET` — случайный секрет не короче 32 байт.
   - `ADMIN_EMAIL` — почта первого администратора.
   - `ADMIN_SETUP_TOKEN` — отдельный случайный секрет не короче 32 байт.
   - `PAYMENT_ENCRYPTION_KEY` — ключ AES длиной 32 байта в Base64 или hex.
   - `RESEND_API_KEY` — API-ключ Resend для отправки писем с кодами.
   - `EMAIL_FROM` — подтверждённый отправитель Resend, например
     `Символ Спорта <noreply@ваш-домен.ru>`.
4. Сгенерировать случайные значения можно локально, не публикуя их:

   ```bash
   node -e "const c=require('node:crypto'); console.log('JWT_SECRET='+c.randomBytes(48).toString('base64url')); console.log('ADMIN_SETUP_TOKEN='+c.randomBytes(48).toString('base64url')); console.log('PAYMENT_ENCRYPTION_KEY='+c.randomBytes(32).toString('base64'))"
   ```

5. Создайте деплой. Таблицы и начальный каталог создаются API автоматически
   при первом запросе. Откройте магазин, нажмите «Войти» → «Зарегистрироваться»,
   укажите `ADMIN_EMAIL` и введите `ADMIN_SETUP_TOKEN`. После успешного
   создания администратора удалите `ADMIN_SETUP_TOKEN` из настроек Vercel и
   запустите повторный деплой. Обычная регистрация создаёт только покупателя;
   способа назначить себе администратора из браузера нет.
6. Войдите в панель администратора → «ЮKassa». Введите идентификатор магазина
   и секретный ключ из кабинета ЮKassa. Секрет шифруется AES-256-GCM с
   `PAYMENT_ENCRYPTION_KEY`, не возвращается клиенту и не сохраняется в
   браузере. Этот ключ шифрования необходимо надёжно хранить и резервировать:
   без него ранее сохранённый ключ ЮKassa нельзя расшифровать.
7. В кабинете ЮKassa укажите URL уведомлений
   `https://ВАШ-ДОМЕН/api/payments/webhook` и включите события
   `payment.succeeded` и `payment.canceled`. Статус уведомления дополнительно
   проверяется запросом к API ЮKassa; само входящее уведомление не считается
   доказательством оплаты. Проверьте полный сценарий тестовым платежом.

Для Preview-деплоев задайте отдельные тестовые базу данных и ключи/магазин.
Не подключайте тестовые или Preview-среды к боевым платежам.

## Развёртывание на Layero

Проект настроен как Node.js runtime: один сервер отдаёт собранный Vite-интерфейс
и обрабатывает `/api/*`. Файл `layero.json` задаёт этот режим и команды сборки
и запуска; приложение слушает `0.0.0.0:$PORT`. Данные сохраняются во внешнем
PostgreSQL, локальный диск контейнера для данных не используется.

1. Создайте PostgreSQL-базу в Layero или подключите внешнюю и сохраните
   `DATABASE_URL`. Для Layero Database скопируйте строку подключения из панели.
2. В корне проекта выполните `npx layero@latest deploy` и завершите вход по
   подсказке CLI. Чтобы развернуть каталог `sport_symbol` из корня репозитория,
   сначала перейдите в него.
3. В Layero Project → Environment Variables добавьте `DATABASE_URL`,
   `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_SETUP_TOKEN`,
   `PAYMENT_ENCRYPTION_KEY`, `RESEND_API_KEY` и `EMAIL_FROM`. Используйте те же
   требования к секретам и отправителю, что указаны выше для Vercel.
4. После сохранения переменных повторно запустите деплой. Таблицы создаются при
   первом обращении к API. URL уведомлений ЮKassa:
   `https://ВАШ-ДОМЕН/api/payments/webhook`.

Runtime Layero stateless: база должна быть PostgreSQL, а не файл или SQLite.
`layero.json` настраивает только Layero; Vercel продолжает использовать
`vercel.json` и serverless-функцию в `api/`.

## Роли и возможности

- **Покупатель:** регистрация с подтверждением почты четырёхзначным кодом,
  вход и восстановление пароля по одноразовому коду; JWT хранится в
  `HttpOnly`, `Secure`, `SameSite=Lax` cookie; корзина синхронизируется с
  сервером и доступна после повторного входа; оформление создаёт заказ и
  перенаправляет на ЮKassa.
- **Администратор:** добавление товаров, изменение цен, просмотр всех корзин
  зарегистрированных покупателей (в том числе неоплаченных и пустых),
  просмотр заказов и настройка ЮKassa.
- Корзины разделены по аккаунтам, а API администратора проверяет роль и в
  JWT, и в базе. Изменяющие запросы проверяют источник, вход ограничен по
  числу попыток. Пароли хешируются `scrypt`.
- Сервер перепроверяет цены и количество из базы и сверяет сумму, валюту и
  статус платежа с ЮKassa. Данные карт сайт не принимает и не хранит.

## Важно перед реальными продажами

Перед регистрацией проверьте, что в Resend добавлен и подтверждён домен
отправителя, а `RESEND_API_KEY` и `EMAIL_FROM` указаны для Production и
Preview в Vercel. Коды действуют 10 минут; для уже существующих аккаунтов
почта считается подтверждённой после миграции. Для соответствия требованиям
онлайн-кассы настройте в кабинете ЮKassa чеки, НДС/систему налогообложения и
обязательные данные покупателя; текущая форма оплаты не заменяет фискальную
настройку магазина. Заполните реальные контактные данные, условия доставки,
возврата и документы магазина до приёма платежей.

JWT и ключ шифрования должны быть разными, храниться только в Vercel
Environment Variables и не попадать в git, логи или клиентский код. При
ротации `PAYMENT_ENCRYPTION_KEY` сначала расшифруйте и заново сохраните ключ
ЮKassa старым ключом, иначе сохранённые реквизиты станут недоступны.

## Структура

- `src/` — интерфейс и корзина.
- `api/[...path].js` — Node.js API-функции Vercel.
- `server/_lib.js` — PostgreSQL, JWT, хеширование паролей и шифрование
  реквизитов оплаты.
- `src/data/products.js` — исходный демонстрационный каталог; при первом
  запросе его товары добавляются в базу, после чего база хранит актуальные
  цены.
