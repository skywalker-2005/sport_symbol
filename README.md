# Символ Спорта

Магазин спортивных наград: React/Vite, Node.js API и PostgreSQL. API управляет
каталогом, аккаунтами, корзинами, заказами и оплатой через ЮKassa. Backend можно
развернуть отдельно на Render; frontend может оставаться на Layero или другом
хостинге.

## Разработка

Нужны Node.js 22 или новее и локально установленная PostgreSQL. Создайте
отдельную базу и роль для разработки (в `psql` или pgAdmin выполните команды
по отдельности, заменив пароль на свой):

```sql
CREATE ROLE sport_symbol_local LOGIN PASSWORD 'ваш-локальный-пароль';
CREATE DATABASE sport_symbol_local OWNER sport_symbol_local;
```

В Windows PowerShell скопируйте шаблон:

```powershell
Copy-Item local.env.example local.env
```

В `local.env` укажите пароль роли в `DATABASE_URL`, затем задайте случайные
`JWT_SECRET` и `PAYMENT_ENCRYPTION_KEY`. Создать их можно локально:

```bash
node -e "const c=require('node:crypto'); console.log('JWT_SECRET='+c.randomBytes(48).toString('base64url')); console.log('PAYMENT_ENCRYPTION_KEY='+c.randomBytes(32).toString('base64'))"
```

Установите зависимости и запустите одной командой сборку frontend и backend:

```bash
npm ci
npm run start:local
```

Откройте `http://127.0.0.1:3000`. Этот сервер отдаёт frontend и `/api` с
одного адреса, поэтому локальный сайт сразу использует настроенную PostgreSQL.
Таблицы и каталог создаются автоматически при первом запросе. В панели
администратора можно загрузить JPEG/PNG/WebP до 10 МБ: сервер уменьшает
изображение и сохраняет JPEG до 1 МБ в PostgreSQL вместе с товаром.

Локальная учётная запись администратора:

```text
Логин:  admin@localhost.test
Пароль: SimvolLocal-Admin!2026
```

Она автоматически создаётся в локальной базе. Локальный режим включён только
при `NODE_ENV=development` и `LOCAL_DEV_ADMIN=true`, требует PostgreSQL на
loopback-адресе и слушает только `127.0.0.1`. В production этот dev-администратор
недоступен. Не используйте локальную базу для боевых данных.

Пользовательские регистрации тоже работают: в локальном режиме четырёхзначные
коды подтверждения и сброса пароля выводятся в терминал процесса вместо
отправки почты. Для реальных писем настройте Resend по инструкции
развёртывания. `npm run dev` запускает только Vite; для полностью работающего
локального сайта используйте `npm run start:local`.

### Layero frontend + локальный backend через ngrok

Такой режим нужен для разработки: Layero показывает frontend, а его API-запросы
идут через HTTPS ngrok-туннель на ваш компьютер.

1. Установите ngrok CLI, создайте/используйте аккаунт ngrok и добавьте токен
   локально командой `ngrok config add-authtoken <ВАШ_NGROK_AUTHTOKEN>`. Токен
   хранится в пользовательской конфигурации ngrok — не добавляйте его в Git,
   `local.env` или Layero.
2. В `local.env` задайте `CORS_ORIGINS` точно равным адресу Layero frontend,
   например `https://sport-symbol-develop.layero.app` (без завершающего `/`).
   Убедитесь, что `DATABASE_URL` указывает только на локальную PostgreSQL.
3. Чтобы вход администратора работал через публичную страницу Layero, задайте
   в `local.env` `ADMIN_EMAIL` и отдельный `ADMIN_SETUP_TOKEN` не короче
   32 байт. Создайте их случайными значениями, например:

   ```bash
   node -e "const c=require('node:crypto'); console.log('ADMIN_EMAIL=ваш-адрес@example.com'); console.log('ADMIN_SETUP_TOKEN='+c.randomBytes(48).toString('base64url'))"
   ```

   Через туннель фиксированный локальный аккаунт
   `admin@localhost.test` / `SimvolLocal-Admin!2026` намеренно отключён.
   Зарегистрируйте заданный `ADMIN_EMAIL` на сайте с этим setup token и
   подтвердите почту кодом из терминала backend. Не используйте короткий или
   повторно применяемый пароль.

4. Запустите `npm run start:tunnel`. Скрипт поднимет API только на
   `127.0.0.1`, временно отключит dev-администратора, запустит ngrok и выведет
   HTTPS URL backend. При закрытии процесса API и туннель завершатся.
5. Скопируйте HTTPS URL туннеля в переменную сборки Layero `VITE_API_URL` и
   запустите новый deploy frontend. `CORS_ORIGINS` при этом остаётся origin
   сайта Layero, а не адресом туннеля. Для входа API выставляет
   `SameSite=None; Secure` cookie. Если браузер блокирует third-party cookies,
   авторизация между этими доменами не сохранится — потребуется разрешить
   cookies либо настроить frontend/API на общем домене.
6. URL туннеля может меняться при перезапуске ngrok. Обновляйте `VITE_API_URL`
   и повторно deploy frontend. С reserved ngrok domain можно закрепить адрес:
   укажите его в `NGROK_DOMAIN` в `local.env`.

Туннель делает API доступным из интернета. Задайте точный `CORS_ORIGINS`,
держите компьютер, PostgreSQL и backend включёнными и остановите туннель,
когда ссылка больше не нужна. Не используйте этот режим для реальных заказов,
платежей или производственных данных.

## Backend на Render

В репозитории есть `render.yaml` для отдельного Node.js API-сервиса:
`render-server.js` принимает `/api/*`, а frontend-файлы не раздаются этим
сервисом. Runtime слушает `0.0.0.0:$PORT`; данные и сессии хранятся в
PostgreSQL, не на диске Render.

1. Создайте PostgreSQL в Render (или используйте внешнюю PostgreSQL-базу).
   Для сервиса и базы Render выберите один регион. Скопируйте **Internal
   Database URL** базы; для внешней базы используйте предоставленную ей строку
   подключения.
2. В Render выберите **New → Blueprint** и укажите этот Git-репозиторий.
   Render прочитает `render.yaml`, создаст Web Service `simvol-sporta-api` и
   предложит заполнить секреты. Если настраиваете сервис вручную, используйте:
   - Root Directory: каталог приложения (тот, где лежат `package.json` и
     `render.yaml`);
   - Build Command: `npm ci`;
   - Start Command: `npm run start:api`;
   - Health Check Path: `/api/health`.
3. В настройках Web Service → **Environment** задайте:
   - `DATABASE_URL` — PostgreSQL URL.
   - `CORS_ORIGINS` — точный origin frontend, без завершающего `/`, например
     `https://sport-symbol-develop.layero.app`. Несколько origin перечисляются
     через запятую.
   - `JWT_SECRET` — уникальный случайный секрет не короче 32 байт.
   - `ADMIN_EMAIL` — почта, которой будет принадлежать первая админская
     учётная запись.
   - `ADMIN_SETUP_TOKEN` — отдельный случайный секрет для её первичной
     регистрации.
   - `PAYMENT_ENCRYPTION_KEY` — ключ шифрования длиной 32 байта в Base64 или
     hex.
   - `RESEND_API_KEY` — API-ключ Resend для подтверждения почты и сброса пароля.
   - `EMAIL_FROM` — подтверждённый отправитель Resend, например
     `Символ Спорта <noreply@ваш-домен.ru>`.
   - `CONTACT_EMAIL` — почта для заявок с контактной формы.
4. Сгенерируйте секреты на своём компьютере и скопируйте значения в Environment
   Render. Не отправляйте их в чат и не сохраняйте в Git:

   ```bash
   node -e "const c=require('node:crypto'); console.log('JWT_SECRET='+c.randomBytes(48).toString('base64url')); console.log('ADMIN_SETUP_TOKEN='+c.randomBytes(48).toString('base64url')); console.log('PAYMENT_ENCRYPTION_KEY='+c.randomBytes(32).toString('base64'))"
   ```

   Можно использовать другой отдельный 32-байтовый ключ для каждого секрета;
   не задавайте одно значение для нескольких переменных.

5. Создайте сервис и дождитесь деплоя. Откройте
   `https://ИМЯ-СЕРВИСА.onrender.com/api/health`: ответ `200` и `"ok": true`
   означает, что backend подключился к базе. Таблицы и начальный каталог
   создаются при первом обращении к API.
6. Если frontend размещён отдельно, задайте `VITE_API_URL` равным адресу
   backend, например `https://ИМЯ-СЕРВИСА.onrender.com`, в **переменных сборки
   frontend** и пересоберите/повторно разверните frontend. Это значение
   встраивается в сборку; изменение только runtime-переменных Render его не
   изменит. Для Layero укажите `VITE_API_URL` в переменных проекта до нового
   деплоя. API на Render должен содержать origin этого frontend в
   `CORS_ORIGINS`.
7. Войдите в зарегистрированную админскую учётную запись и сохраните настройки
   ЮKassa в панели администратора. Уведомления ЮKassa настройте на
   `https://ИМЯ-СЕРВИСА.onrender.com/api/payments/webhook`, включив события
   `payment.succeeded` и `payment.canceled`.

### Получение доступа администратора

Администратор не создаётся с готовым паролем: его email задаётся в Render, а
пароль вы придумываете при регистрации на сайте.

1. В Render → ваш backend → **Environment** задайте `ADMIN_EMAIL` — личный
   адрес, к которому у вас есть доступ. На него придёт письмо подтверждения.
2. Локально выполните команду генерации выше и скопируйте значение
   `ADMIN_SETUP_TOKEN` в одноимённую переменную Render. Этот код не приходит по
   почте: это секрет настройки, который вы создаёте сами.
3. Откройте сайт, выберите **Войти → Регистрация** и укажите точно этот
   `ADMIN_EMAIL`, придумайте пароль. В поле **«Код настройки администратора
   (если вы администратор)»** вставьте `ADMIN_SETUP_TOKEN`.
4. Введите четырёхзначный код из письма Resend, чтобы подтвердить email.
   После подтверждения войдите с указанными email и паролем; появится кнопка
   «Админ».
5. Удалите `ADMIN_SETUP_TOKEN` из Environment Render после успешной
   регистрации. `ADMIN_EMAIL` оставьте. Не публикуйте пароль и setup token.

Если пользователь с этим email уже зарегистрирован как покупатель, смените
роль только для своего подтверждённого аккаунта запросом в SQL-консоли базы:

```sql
UPDATE users SET role = 'admin'
WHERE email = 'ваш-адрес@example.com' AND email_verified = TRUE;
```

После этого выйдите из сайта и войдите снова. Пароль администратора — тот,
который был задан при регистрации; отдельного стандартного пароля нет.

## Frontend и настройки домена

Frontend может остаться на Layero. Установите для его production-сборки
`VITE_API_URL` в URL Render backend без завершающего `/`, а в Render укажите
его точный адрес в `CORS_ORIGINS`. Если frontend развернут на другом хостинге,
настройте там ту же build-time переменную и пересоберите сайт. Для локального
frontend без `VITE_API_URL` API запрашивается с того же origin.

Backend устанавливает защищённую HttpOnly cookie сессии и разрешает запросы
только от origin из `CORS_ORIGINS`. Для межсайтовых cookie браузер должен
разрешать third-party cookies. Для максимально надёжного входа рекомендуется
настроить собственные frontend и API под одним доменом верхнего уровня
(например, `shop.example.ru` и `api.example.ru`) либо разместить frontend и
backend на одном origin.

### Переменные окружения

| Переменная               | Назначение                                                          |
| ------------------------ | ------------------------------------------------------------------- |
| `DATABASE_URL`           | PostgreSQL connection string                                        |
| `CORS_ORIGINS`           | Разрешённые origin frontend; разделитель — запятая                  |
| `JWT_SECRET`             | Подпись сессий, минимум 32 байта                                    |
| `LOCAL_DEV_ADMIN`        | Локальный dev-администратор; включать только в `local.env`          |
| `TUNNEL_MODE`            | Ограниченный API-only режим для ngrok; включает межсайтовые cookies |
| `NGROK_DOMAIN`           | Необязательный reserved ngrok HTTPS-домен для туннеля               |
| `ADMIN_EMAIL`            | Email первой админской учётной записи                               |
| `ADMIN_SETUP_TOKEN`      | Временный секрет её первичной регистрации                           |
| `PAYMENT_ENCRYPTION_KEY` | Шифрование ключа ЮKassa, 32 байта                                   |
| `RESEND_API_KEY`         | Отправка кодов подтверждения и восстановления пароля                |
| `EMAIL_FROM`             | Подтверждённый адрес отправителя Resend                             |
| `CONTACT_EMAIL`          | Получатель заявок контактной формы                                  |
| `VITE_API_URL`           | URL backend для сборки отдельно размещаемого frontend               |

`VITE_API_URL` — frontend build-time переменная, остальные значения нужны
серверу. Не добавляйте секреты в `VITE_*` переменные: они встраиваются в
публичный JavaScript сайта.

## Диагностика

- `GET /api/health` показывает наличие конфигурации и доступность PostgreSQL,
  не раскрывая значения секретов.
- `GET /api/products` должен вернуть каталог после успешного подключения базы.
  Если health check или каталог не работает, смотрите **Logs** Render Web
  Service и проверьте `DATABASE_URL`, SSL и доступность базы.
- Ошибка CORS означает, что origin frontend отсутствует или не совпадает с
  `CORS_ORIGINS`. Укажите origin с протоколом, без пути и без завершающего `/`.
- Если API отвечает, но вход не сохраняется, проверьте, что браузер разрешает
  cookies для backend и что frontend отправляет запросы с credentials. При
  ограничении third-party cookies используйте frontend и API под общим
  доменом верхнего уровня.
- Если письма не приходят, проверьте `RESEND_API_KEY`, подтверждение домена и
  `EMAIL_FROM` в Resend. Для формы заявок также проверьте `CONTACT_EMAIL`.

## Оплата ЮKassa

В панели администратора откройте вкладку «ЮKassa» и введите идентификатор
магазина и секретный ключ из кабинета ЮKassa. Ключ шифруется сервером с помощью
`PAYMENT_ENCRYPTION_KEY` и не возвращается клиенту. Сохраните этот ключ
шифрования отдельно: без него ранее сохранённый ключ ЮKassa нельзя
расшифровать. В кабинете ЮKassa задайте URL уведомлений
`https://ИМЯ-СЕРВИСА.onrender.com/api/payments/webhook`.

Реквизиты магазина, предоставленные владельцем:

```text
Наименование: Индивидуальный предприниматель Щукин Олег Валерьевич
ИНН:          772171824020
ОГРНИП:       325774600323142
Адрес магазина: Золоторожский Вал, 11с22, спортивный центр «СимволСпорта»
Адрес склада:   проезд Завода Серп и Молот, 12
Телефон:        8 (495) 778-55-88
```

Перед реальными продажами проверьте требования ЮKassa к документам,
фискализации, доставке и возвратам. Используйте отдельную тестовую базу и
тестовый магазин для проверки платежей.

## Структура

- `src/` — React-интерфейс и каталог.
- `render-server.js` — отдельный API-сервер для Render.
- `server.js` — сервер, который отдаёт frontend и API на одном origin.
- `local.env.example` — шаблон переменных для локального запуска.
- `scripts/start-tunnel.js` — запускает локальный API через ngrok.
- `api/[...path].js` — маршруты API.
- `server/_lib.js` — PostgreSQL, почта, сессии и шифрование платёжных данных.
- `render.yaml` — настройки Web Service Render.
